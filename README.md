# Refdesk

Refdesk 是面向 Windows x64 和 Apple Silicon Mac 的 Rust Git 桌面客户端。左边放仓库和分支，中间是提交图，右边是提交和变更文件，下方是并排 diff。左栏、右栏和 diff 的分隔条可以拖动。

## 启动

Windows 上双击项目根目录的 **Start-Refdesk.cmd**，或者在 PowerShell 运行：

    .\Start-Refdesk.cmd

启动器和直接运行 `refdesk.exe` 默认共用 `%APPDATA%\Refdesk\settings.json`，用它恢复已登记仓库和上次活动仓库。需要使用独立会话时，可通过 `REFDESK_CONFIG` 指定文件。

Apple Silicon Mac 上解压 macOS ZIP，然后从 Finder 打开 `Refdesk.app`。仓库操作需要有可用的 Git。

从旧版启动器迁移时，若用户目录下还没有 `settings.json`，可将项目里的 `.local/settings.json` 整份复制过去，保留原有仓库、分支选择和 Diff Tools 设置。

程序需要 PATH 中有 Git。可重复用 `--repo` 指定工作树，用 `--import-smartgit` 导入本机 SmartGit 的 Diff Tools。

- 启动时先恢复上次选中的仓库。提交历史与工作树状态分别读取，当前提交图先就绪后，后台逐个预读其他登记仓库的历史。首次切过去再读取那个工作树的状态。
- 点击或双击仓库切换当前视图。打开父仓库后，仓库树会自动列出它的子模块，点击已检出的子模块才加载其提交图和工作树。左上「···」可以登记关联 worktree 或关闭其他已登记仓库的后台预读。
- 中央提交图用彩色线路表示父子关系，菱形表示合并提交，带外环的是 HEAD。分支面板默认勾选 HEAD，可以勾选多条本地分支、远程分支及标签，同一张图显示它们的共同和独有历史。选中本地分支或指向本地分支的 HEAD 时，图自动包含已有的远程上游历史，远程分支无需另行勾选。Ctrl 点击分支名也可增减选择，普通点击分支名只勾选该引用。本地、远程和标签各自按名称中的 / 组成可折叠的目录树。目录复选框可以批量选择下级引用。搜索会展开匹配路径，搜索期间整组勾选只作用于匹配项。也可点「全部」显示全部引用。每个仓库独立记住勾选项。Ctrl+F 可搜提交说明、作者、SHA 和分支名。选中提交后按 Ctrl 点击另一条，可比较两条提交的文件。
- 本地分支旁显示跟踪分支和提交差（=、+领先、−落后）。若本地和上游名称相同，列表缩写为远程名，悬停可看完整跟踪分支。图形在同一提交合并显示跟踪标签，两端位置不同时各显示在自己的可见提交。计数来自本地远程跟踪引用，刷新和获取后更新。
- 在提交图页头的工具栏可对当前仓库获取、拉取、推送和刷新。也可按 F5 刷新当前仓库。
- 右键本地分支，选择「设置跟踪分支…」，可选择或更换已有的远端分支。推送未设置跟踪分支的本地分支时，可以先保存一个已有的跟踪分支，也可以勾选「本次推送并自动建立跟踪分支」，选择远端后推送同名分支并设置跟踪。
- 右键历史提交可复制完整消息或 SHA、检出该提交、合并或摘取到当前 HEAD，以及在该提交上创建分支或轻量标签。检出提交会进入分离 HEAD。摘取合并提交时需选择主线父提交。
- 进行中的合并、摘取和变基显示在提交图上方，支持从终端发起后回到 Refdesk 处理。「查看冲突」定位冲突文件，可在记事本编辑工作树文件并暂存解决结果。Git 确认可继续后可用「继续」，摘取和变基还可跳过当前提交。跳过和中止会先确认。窄窗从「更多」访问次要动作。Git 请求编辑变基说明时，右上角会显示当前说明，保存后继续变基。取消编辑可从状态条重新打开，普通提交草稿单独保留。编辑变基计划、拆分提交等步骤由终端处理。
- 右键「工作树 / 暂存区」可进入提交编辑区、暂存全部，或从暂存区恢复已跟踪文件的未暂存改动。丢弃未暂存改动会保留已有暂存和未跟踪文件。
- 在右侧文件区输入文件名或相对路径可即时筛选，点击匹配文件预览 diff。点击工作树文件列表的「已暂存」或「未暂存」标题可独立展开或折叠对应分组。工作树里的文件可右键暂存或取消暂存，再填写说明提交。切换视图会保留本次运行中的提交草稿。拉取使用 fast-forward only。
- 在未暂存分组按住 Ctrl 点击多个文件，再点「暂存所选」或从已选行的右键菜单触发。选中的文件由同一条 Git 命令暂存。修改筛选条件会清除多选，单文件仍可直接右键暂存。
- 在提交图中切换到新提交或双提交对比时，文件区自动选中当前列表的第一项，下方随即显示其差异。已输入筛选词时，自动选中第一条匹配的文件。
- 暂存和暂存全部成功后，可确认的文件分组和计数先局部更新，再由后台的 Git 状态校准。取消暂存、部分暂存和重命名等情况先读取受影响的路径。已选文件随分组移动，差异切换到对应版本。
- Git 命令结束时先反馈结果，再校准操作影响的数据。创建本地引用时，已加载的目标行会先显示标签或分支名。提交、检出和同步等影响 HEAD 的操作会确认实际引用和提交，再刷新历史和工作树。获取和推送使用真实引用和历史更新跟踪信息。
- 文本差异为识别到的代码显示语法颜色，在替换行内用底色标出改变的片段。源码先显示，语法高亮在后台补上。用「↑」「↓」跳转到上一处或下一处连续变更，勾选「仅显示变更」后仍按原有变更块跳转。
- Excel 内置视图按坐标比较工作表、值和公式。「Excel Diff ↗」会用已匹配的外部规则打开两个文件版本。工具配置可以从 SmartGit 导入，也可以手动添加和排序。按从上到下的规则顺序匹配。
- 选中文件时，下方差异窗格立即显示文件名与左右版本表头。每侧就绪后即可查看，空版本和读取失败也会在对应一侧显示。文本行对齐和工作簿变化在两侧可比较后补上。
- 选中 PNG、JPEG、BMP、GIF 或 WebP 文件，下方差异窗格会并排显示旧图和新图，标注像素尺寸，并用棋盘格显示透明区域。默认使用共同比例适应窗格，点击「100%」可按原始像素查看并拖动两侧。动态图显示首帧。Git LFS 图片优先使用本地缓存，缺少对象时通过 Git LFS 在后台按需下载。
- 标题栏「外观」内置冷白蓝、暖白棕两套亮色和暖灰绿、深蓝灰两套暗色。首次使用默认暖灰绿。切换立即生效，重启时恢复所选主题。

## 外部主题

Refdesk 启动时读取 `%APPDATA%\Refdesk\themes` 下的独立 JSON 文件。设置 `REFDESK_CONFIG` 时，读取该会话文件旁的 `themes` 子目录。「外观」菜单底部的「自定义主题...」可直接打开该目录。添加、编辑或删除文件后重启，再在「外观」中选择。

- 新版首次使用当前数据目录时会写入浅灰蓝和炭灰紫示例，保留已有同名文件。之后删除示例也不会重新生成。可复制 [浅灰蓝](assets/themes/neutral-light.json) 或 [炭灰紫](assets/themes/neutral-dark.json) 作为模板。文件名去掉 `.json` 是会话记录的主题 ID，英文字母按小写匹配。为新主题使用不同的文件名。
- `name` 是菜单名称，`mode` 为 `light` 或 `dark`，`palette` 包含模板中的全部色板字段。颜色使用 `#RRGGBB`，`lanes` 有八种提交轨道色，`shadow` 为 0 至 255 的阴影透明度值，255 最深。
- Refdesk 会跳过无效文件及与内置 ID 冲突的文件。所选主题缺失时使用暖灰绿，恢复文件后可继续使用原主题。

## 运行日志

Windows 桌面版默认在 `%LOCALAPPDATA%\Refdesk\logs` 写入 INFO 级别日志。日志记录启动与退出、仓库激活、提交图和状态就绪、Git 操作及差异失败。文件名包含启动时间、进程 ID 和 UTC 日期，按日滚动，自动清理超过七天的已关闭日志。

分支筛选的 INFO 日志包含等待新图的耗时、最大绘制间隔和缺页帧数。DEBUG 日志可以按请求号查看分页新增了多少条提交、从磁盘读回了多少页，以及搜索匹配数。

启动前可设置 `REFDESK_LOG_DIR` 指定日志目录，或设置 `REFDESK_LOG_LEVEL=DEBUG` 记录后台请求和缓存细节。支持 `TRACE`、`DEBUG`、`INFO`、`WARN`、`ERROR`、`OFF`。未设置或值无效时使用 INFO。日志只保存在本机，工作树用会话内的匿名编号表示。

## 构建和验证

需要 Rust 1.88 或以上及 Git。Windows 使用原生 Windows Rust 工具链，使用 windows-gnu 时还需要 GNU Binutils。Apple Silicon 使用 `aarch64-apple-darwin` 和 Xcode 命令行工具。两端构建、校验和发布见 [打包与发布](docs/PACKAGING.md)。

    cargo build --release --locked

Windows Release 构建输出到 `target/release/refdesk.exe`。启动器优先使用 `artifacts/refdesk-current.exe`，便于桌面版运行时重编译。单元测试、回归测试和两端 CI 检查见 [测试与验收](docs/TESTING.md)。

## 0.2 范围

提交历史每批最多读取 32 条，滚动接近当前末尾时自动加载下一批，直到所选分支的历史末尾。视口附近的页留在内存，滚远的页可从会话缓存读回，也可通过提交搜索定位。合并提交详情默认与第一父提交比较。父仓库在文件列表中以 Gitlink 显示子模块指针变化。工作树文件列表遵循 Git 生效的子模块忽略配置，`ignore = all` 隐藏未暂存的指针变化，已暂存的指针变化仍会显示。尚未检出的子模块名称使用次要文字色，悬停时显示红色状态提示。初始化和更新子模块需另行通过 Git 执行。内置 Excel 使用表名和物理单元格坐标，不包含格式和按业务主键对齐的比较。从 Refdesk 发起变基、贮藏和三方冲突编辑器列于开发清单。

开发进度和验收记录在 docs 下。仓库会话对照和本机字节码位置见 [SmartGit 行为参考](docs/SMARTGIT_REFERENCE.md)。
