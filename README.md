# Refdesk

Refdesk 是 Windows 上的 Rust Git 桌面客户端。左边放仓库和分支，中间是提交图，右边是提交和变更文件，下方是并排 diff。左栏、右栏和 diff 的分隔条可以拖动。

## 启动

双击项目根目录的 **Start-Refdesk.cmd**，或者在 PowerShell 运行：

    .\Start-Refdesk.cmd

启动器和直接运行 `refdesk.exe` 默认共用 `%APPDATA%\Refdesk\settings.json`，用它恢复已登记仓库和上次活动仓库。需要使用独立会话时，可通过 `REFDESK_CONFIG` 指定文件。

从旧版启动器迁移时，若用户目录下还没有 `settings.json`，可将项目里的 `.local/settings.json` 整份复制过去，保留原有仓库、分支选择和 Diff Tools 设置。

程序需要 PATH 中有 Git。可重复用 `--repo` 指定工作树，用 `--import-smartgit` 导入本机 SmartGit 的 Diff Tools。

- 启动时先恢复上次选中的仓库。提交历史与工作树状态分别读取，当前提交图先就绪后，后台逐个预读其他登记仓库的历史。首次切过去再读取那个工作树的状态。
- 点击或双击仓库切换当前视图。打开父仓库后，仓库树会自动列出它的子模块，点击已检出的子模块才加载其提交图和工作树。左上「···」可以登记关联 worktree 或关闭其他已登记仓库的后台预读。
- 中央提交图用彩色线路表示父子关系，菱形表示合并提交，带外环的是 HEAD。分支面板默认勾选 HEAD，可以勾选多条本地分支、远程分支及标签，同一张图显示它们的共同和独有历史。Ctrl 点击分支名也可增减选择，普通点击分支名只看该引用。本地、远程和标签各自按名称中的 / 组成可折叠的目录树。目录复选框可以批量选择下级引用。搜索会展开匹配路径，搜索期间整组勾选只作用于匹配项。也可点「全部」显示全部引用。每个仓库独立记住选择。Ctrl+F 可搜提交说明、作者、SHA 和分支名。选中提交后按 Ctrl 点击另一条，可比较两条提交的文件。
- 本地分支旁显示跟踪分支和提交差（=、+领先、−落后）。若本地和上游名称相同，列表缩写为远程名，悬停可看完整跟踪分支。图形在同一提交合并显示跟踪标签，两端位置不同时各显示在自己的可见提交。计数来自本地远程跟踪引用，刷新和获取后更新。
- 点右侧文件预览 diff。工作树里的文件可右键暂存或取消暂存，再填写说明提交。切换视图会保留本次运行中的提交草稿。拉取使用 fast-forward only。
- 文本差异栏用「↑」「↓」跳转到上一处或下一处连续变更，勾选「仅显示变更」后仍按原有变更块跳转。
- Excel 内置视图按坐标比较工作表、值和公式。「Excel Diff ↗」会用已匹配的外部规则打开两个文件版本。工具配置可以从 SmartGit 导入，也可以手动添加和排序。按从上到下的规则顺序匹配。
- 标题栏「外观」提供冷白蓝、暖白棕两套亮色和暖灰绿、深蓝灰两套暗色。切换立即应用到工作台并保存到当前会话，首次使用默认暖灰绿。

## 运行日志

Windows 桌面版默认在 `%LOCALAPPDATA%\Refdesk\logs` 写入 INFO 级别日志。日志记录启动与退出、仓库激活、提交图和状态就绪、Git 操作及差异失败。文件名包含启动时间、进程 ID 和 UTC 日期，按日滚动，自动清理超过七天的已关闭日志。

分支筛选的 INFO 日志包含等待新图的耗时、最大绘制间隔和缺页帧数。DEBUG 日志可以按请求号查看分页新增了多少条提交、从磁盘读回了多少页，以及搜索匹配数。

启动前可设置 `REFDESK_LOG_DIR` 指定日志目录，或设置 `REFDESK_LOG_LEVEL=DEBUG` 记录后台请求和缓存细节。支持 `TRACE`、`DEBUG`、`INFO`、`WARN`、`ERROR`、`OFF`。未设置或值无效时使用 INFO。日志只保存在本机，工作树用会话内的匿名编号表示。

## 构建和验证

Rust 1.88 或以上、原生 Windows Rust 工具链及 Git。使用 windows-gnu 工具链时需要 GNU Binutils。Windows x64 的工具链配置、Release EXE 打包和校验步骤见 [Windows 打包流程](docs/PACKAGING.md)。

    cargo build --release --locked

Release 构建输出到 target/release/refdesk.exe。启动器优先使用 artifacts/refdesk-current.exe，便于桌面版运行时重编译。单元测试、回归测试、Windows CI 和完整检查命令见 [测试与验收](docs/TESTING.md)。

## 0.1 范围

提交历史每批最多读取 32 条，滚动接近当前末尾时自动加载下一批，直到所选分支的历史末尾。视口附近的页留在内存，滚远的页可从会话缓存读回，也可通过提交搜索定位。合并提交详情默认与第一父提交比较。父仓库在文件列表中以 Gitlink 显示子模块指针变化。尚未检出的子模块在仓库树中显示红色状态提示，初始化和更新子模块需另行通过 Git 执行。内置 Excel 使用表名和物理单元格坐标，不包含格式和按业务主键对齐的比较。0.1 尚未提供 merge、rebase、stash 和冲突解决界面。

开发进度和验收记录在 docs 下。仓库会话对照和本机字节码位置见 [SmartGit 行为参考](docs/SMARTGIT_REFERENCE.md)。
