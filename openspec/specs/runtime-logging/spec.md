# runtime-logging Specification

## Purpose

为 Windows 上的 Refdesk 保存本机运行诊断记录，让用户在一次会话结束后仍可追查仓库加载、Git 操作和差异比较的失败及耗时。

## Requirements

### Requirement: 本机运行日志默认开启

Windows 图形进程 MUST 默认在 `%LOCALAPPDATA%\Refdesk\logs` 下以 INFO 级别写入 UTF-8 单行日志，并接受 `REFDESK_LOG_DIR` 和 `REFDESK_LOG_LEVEL` 覆盖。日志 MUST 按会话和 UTC 日期命名，自动清理超过七天且已关闭的本应用日志。

#### Scenario: 默认启动及正常退出

- **WHEN** 用户通过图形入口正常启动并关闭 Refdesk，且未提供日志环境变量
- **THEN** 默认目录中可看到本次会话的启动及退出记录
- **AND** 日志文件可和其他并行运行的会话区分

#### Scenario: 自定义日志

- **WHEN** 启动时设置可写的 `REFDESK_LOG_DIR` 和 `REFDESK_LOG_LEVEL=DEBUG`
- **THEN** 日志在指定目录生成并包含 DEBUG 事件

#### Scenario: 显式关闭日志

- **WHEN** 启动时设置 `REFDESK_LOG_LEVEL=OFF`
- **THEN** 当前会话不创建日志文件

#### Scenario: 日志目录无法写入

- **WHEN** 日志目录无法创建或打开
- **THEN** 应用正常进入界面并提示一次日志初始化失败

#### Scenario: 按 UTC 日期轮转

- **WHEN** 后台写入跨越 UTC 日期
- **THEN** 后续日志写入新日期的文件

#### Scenario: 清理过期文件

- **WHEN** 后台写入发现超过七天的已关闭 Refdesk 日志
- **THEN** 过期日志会被清理
- **AND** 其他文件以及仍打开的日志不受影响

### Requirement: 关键操作可按请求追踪

Refdesk MUST 记录应用启动与退出、配置错误、仓库添加与激活、图和状态首次显示、分支筛选绘制结果、Git 写操作以及差异失败。涉及工作树的异步事件 MUST 可按匿名工作树标识和请求编号关联。

#### Scenario: 仓库激活和后台任务

- **WHEN** 工作树激活并首次显示提交图和状态
- **THEN** 日志可关联激活、图就绪和状态就绪，并显示相对激活的耗时
- **AND** 读取失败或慢请求可从日志定位，DEBUG 级别补充缓存、队列、处理和过期结果的信息

#### Scenario: Git 操作和差异

- **WHEN** 用户实际发起 Git 写操作，或差异比较及外部工具启动失败
- **THEN** 日志包含受控的操作类型和结果，以及已知的耗时、错误分类或子进程退出码

#### Scenario: 提交图分页与缓存读回

- **WHEN** 提交图读取下一批历史、恢复缓存页或搜索已加载的记录
- **THEN** DEBUG 日志可关联历史快照和后台请求，并分别记录新增提交数、从磁盘读回的页数或匹配数

#### Scenario: 分支筛选就绪或被替换

- **WHEN** 用户改变分支筛选并等待新提交图，或在新图就绪前再次改变筛选
- **THEN** 运行日志 MUST 记录每个请求的绘制结果、等待耗时、最大绘制间隔、缺页帧数和过期结果数
- **AND** DEBUG 日志记录筛选模式和显式选中的引用数量，字段遵循受控日志约定

### Requirement: 写入有界且使用受控字段

日志 MUST 由有界队列交给后台写入。日志 MUST 使用受控字段，排除完整工作树或文件路径、远端 URL、提交内容、文件和单元格内容以及原始 Git 或子进程输出。

#### Scenario: 队列积压或频繁状态刷新

- **WHEN** 日志队列达到容量，或工作树状态重复触发相同类型的错误
- **THEN** 界面不等待日志 I/O，队列丢失和重复错误均有受控的记录策略

#### Scenario: 工作簿解析

- **WHEN** 启动内部工作簿解析子进程
- **THEN** 父进程记录可用的诊断字段，子进程标准输出仍可作为原有比较协议使用
