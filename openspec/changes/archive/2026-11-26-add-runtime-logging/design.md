## Context

应用通过调度器在后台读取提交历史、工作树状态与差异，并在 UI 收到结果后按工作树和请求编号应用。现有性能文件由 `REFDESK_TIMINGS` 显式启用。Windows 工作簿比较使用同一个可执行文件启动子进程，标准输出是父子进程协议。

## Goals / Non-Goals

首版覆盖本地诊断、默认低频输出、异步关联和保留周期。遥测上传、日志查看器、独立磁盘配额和强制终止时的持久化保证超出本次范围。

## Decisions

- GUI 入口初始化 `tracing`、`tracing-subscriber` 和 `tracing-appender`。仅接收 Refdesk 自己显式声明的事件，保留已有错误提示。工作簿解析子进程继续使用现有协议，由主进程记录启动与结果。
- 优先用 `dirs::data_local_dir()` 定位目录。文件名由程序名、启动时间、PID 和 UTC 日组成。使用有界后台写入队列，队列满时允许丢弃，正常退出时记录已知丢失数并冲刷。
- 后台写入线程启动时和持续运行期间清理超过七天的 Refdesk 文件。Windows 上跳过仍由其他进程打开的文件。
- 使用随机会话密钥生成仅在本进程内稳定的工作树标识。以现有请求编号关联后台任务与可见结果，记录排队、执行和首次呈现耗时。默认只输出生命周期、加载节点、写操作结果、失败和慢请求。对周期性状态故障限频。
- 事件仅接收需要的字段。Git 和工作簿进程的退出码来自实际子进程结果。原始错误文本继续由既有界面展示，日志记录受控分类。保留现有基准计时开关和同一套首次显示判断。

## Risks / Trade-offs

- 队列满或进程被强制终止时可能丢失日志，运行日志只用于诊断。
- 时间滚动和过期清理限制保留周期。通过日志级别和高频事件限频控制单日增长。
- 工作簿子进程异常退出与具体资源上限有时无法区分，记录退出码和已知阶段供诊断。
