## Context

工作区状态和提交历史各自读取。修复需要把工作树根路径、索引条目类型、状态快照和后台请求的归属传过现有边界。

## Goals / Non-Goals

确保索引命令作用于选中的工作树和完整变更。让差异视图使用一致的基准，限制工作簿解析资源，并降低过时请求对新操作的影响。

## Decisions

- 工作树登记与恢复用根路径，写入前核对 Git 实际识别的根目录。
- 状态使用同时携带 HEAD、路径和对象模式的 Git 输出。提交文件列表保留两侧模式，Gitlink 差异使用提交标识。
- 后台读取以工作树和任务类型合并。活动工作树读取优先于其他仓库预读，Git 写入有独立执行线程。
- 切回窗口时，节流期内的状态刷新安排到期后执行。分页状态取已返回的条数、是否仍有记录和统一上限。
- XLSX、XLSM 和 XLSB 通过工作表单元格迭代器保留绝对坐标。Windows 上所有内置工作簿比较都在受内存和 CPU 时间约束的子进程中执行，旧格式继续使用对应的解析器。

## Risks / Trade-offs

- Git 任务开始后可能继续完成。请求编号校验保留作为结果应用边界。
- 稠密格式超出解析内存预算时，界面提示用户改用外部工具。
