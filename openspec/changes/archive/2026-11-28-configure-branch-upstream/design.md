## Context

推送确认沿用仓库的 Git 配置。分支列表在历史快照中显示跟踪关系和提交差。

## Decisions

- 从两个入口后台读取 Git 中的本地分支、上游及可选远端。弹窗按工作树和请求接收结果，用户可在读取期间取消。
- 用 Git 的 `branch --set-upstream-to` 保存已有远端分支。推送引导里的勾选框默认未选中，用户选择远端并确认后，用完整的源、目标引用执行普通的 `push --set-upstream`。写入前复核本次首次推送仍对应当前未配置上游的本地分支。
- 复用共享弹窗、状态反馈和历史校准。已有上游的推送沿用普通确认。根据实际 Git 查询更新跟踪信息、提交差和图中引用。

## Risks / Trade-offs

- 弹窗使用打开时的远端引用。无可用引用时提示获取，引用被删除或推送被拒绝时由 Git 返回失败原因。
- 多远端时由用户选择发布目标。保存已有跟踪分支后再次点击推送可确认并发送提交。
