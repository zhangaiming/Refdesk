## Context

提交行已有打开详情、双提交比较和复制完整 SHA。工作树节点使用右侧现有提交编辑区。仓库写操作由现有后台队列调度并按工作树刷新。

## Decisions

- 右键操作携带点击行的完整对象 ID 和工作树路径。从历史提交创建分支和轻量标签只写引用。检出历史提交进入分离 HEAD。
- 合并与摘取由 Git 应用。摘取合并提交时在确认对话框中选择主线父提交。Git 拒绝或暂停操作时显示原始错误和刷新后的状态，保留 Git 的冲突现场。
- 工作树节点提供暂存全部以及从暂存区恢复未暂存的已跟踪文件。丢弃使用确认对话框并保留已有暂存和未跟踪文件。复用右侧提交编辑区执行正常提交。
- 完整提交说明在后台读取，提交 ID 直接复制。右键菜单与对话框使用工作台现有主题样式。

## Risks / Trade-offs

- 工作区命令以确认时描述的范围作用于 Git 记录。丢弃未暂存改动会覆盖已跟踪文件中的未暂存内容。
- 合并和摘取可能需要解决冲突。Git 会给出恢复提示，使用现有状态区查看冲突文件。

## 历史提交右键菜单

| 分组 | 选项 | 界面设计 | 执行逻辑 |
| --- | --- | --- | --- |
| 查看 | 打开提交详情 | 点击后选中右键所在提交并打开详情。 | 复用单提交选中流程，加载该提交相对父提交的文件变更。 |
| 查看 | 与选中提交比较 | 已有历史提交选区时显示。 | 复用 Ctrl 点击逻辑，以当前选区和右键行建立两提交比较，按图中顺序确定两侧。 |
| 复制 | 复制消息 | 点击后关闭菜单。 | 后台读取右键行的完整提交说明，包括正文，只应用仍属于当前仓库及最新复制请求的结果。读取失败显示错误。 |
| 复制 | 复制 ID | 悬停说明会复制完整 SHA。 | 把右键行的完整对象 ID 直接写入剪贴板，并使较早的 Log 消息复制请求失效。 |
| 提交操作 | 检出提交… | 确认框显示目标短 SHA、仓库路径及分离 HEAD 提示。 | 对完整 SHA 执行 `git switch --detach`。工作树不满足条件时由 Git 拒绝并返回原因。 |
| 提交操作 | 合并提交… | 确认框说明将右键行合并到当前 HEAD。 | 执行 `git merge --no-edit`。根据仓库配置和拓扑快进、创建合并提交或停在冲突状态。 |
| 提交操作 | 摘取提交… | 普通提交直接确认。合并提交列出所有父提交，选择主线之前确认按钮灰显。 | 执行 `git cherry-pick`，对合并提交传入选择的从 1 起算的父提交序号。成功时将改动记为当前 HEAD 上的新提交。出现冲突时显示 Git 错误并保留现场。 |
| 引用 | 创建分支… | 名称框默认聚焦，空名称时确认按钮灰显。框内显示起点提交。 | 校验分支名，执行 `git branch`，把新分支指向该提交。当前检出保留。 |
| 引用 | 创建标签… | 名称框默认聚焦，空名称时确认按钮灰显。框内显示起点提交。 | 校验标签引用，执行 `git tag --no-sign` 创建轻量标签。当前检出保留。 |

写菜单在该仓库已有 Refdesk Git 写操作时灰显。打开确认框时固定源提交和工作树。取消或按 Escape 关闭对话框。Git 命令结束后刷新该工作树的历史和状态，状态栏显示结果。

## 工作树节点右键菜单

| 选项 | 界面设计 | 执行逻辑 |
| --- | --- | --- |
| 提交… | 打开并聚焦右侧提交说明编辑框。 | 复用现有提交面板。用户填写说明并确认后提交索引中的内容。 |
| 暂存全部… | 有未暂存改动且仓库空闲时可用。确认框说明会包括未忽略的新文件。 | 从工作树根目录执行 `git add --all -- .`，统一处理新增、修改和删除。 |
| 丢弃未暂存改动… | 存在可丢弃的已跟踪文件改动，且仓库空闲、无未解决冲突时可用。确认框默认聚焦取消，使用危险操作颜色。 | 从暂存区恢复工作树，保留索引与未跟踪文件。恢复前检查冲突以及文件和目录的占位冲突。发现冲突时返回错误。 |
