## Context

这是对已交付 Refdesk 0.1 的设计补录。代码以 Windows 原生 Rust / eframe / egui 应用为入口，依赖本机 Git 查询与执行。仓库会话、提交图、Git 操作和 diff 按模块分开，界面与可观察边界见五个 delta specs。

## Goals / Non-Goals

- 为当前多仓库工作台记录状态所有权、数据来源、快照边界和验收依据。
- 此版本的待办范围以 `docs/TODO.md` 为准，其中包括合并与变基界面、冲突处理、分页改进和打包签名。

## Decisions

- **仓库按工作树隔离。** `src/app.rs` 用工作树路径组织历史、状态、筛选和草稿，并给异步请求编号。Git 历史与状态分别调度，使提交图不用等待大工作树扫描。只有活动历史可用且没有其他历史请求时，才为下一个候选仓库预读历史。最近读取的工作树状态可复用，显式刷新会重新查询。
- **图与引用依赖实际 Git 数据。** `src/git.rs` 读取提交父 ID、引用及跟踪信息；多选引用作为同一次日志遍历的多个起点，用 date order 将多支历史交织。 `src/graph.rs` 根据父 ID 维护轨道，`src/ui_history.rs` 绘制节点与连线；分支层级和批量筛选由 `src/ui_branches.rs` 管理。
- **共享对齐与密度。** 保持 `DESIGN.md` 的中央阅读区和暖灰主题。提交列计算由表头和正文共用，同行文字使用同一基线。分支圆点使用展开列的空位，数值组贴右，窄窗按预算缩写引用标签。顶栏仓库名与分支名共用基线。
- **Git 操作和文件快照由同一模块解释。** 查询使用只读 Git 选项。写操作由界面明确触发，通过本机 Git 执行。差异明确区分空版本、提交、索引和工作树，并保留重命名时的左右路径。
- **外部配置沿用可导入的格式。** `src/settings.rs` 按顺序选择首个命中规则，实现内置、外部 diff 和独立查看器模式。外部工具的两侧文件在需要时从同一比较请求生成，路径参数在替换后保持原有参数边界。

## Risks / Trade-offs

- 提交图和搜索受当前已加载历史范围约束。达到 3,000 条时界面显示上限，分页优化留在后续计划。
- 内置 Excel 按工作表名和坐标比较，适合跟踪同位置值或公式。格式或业务主键匹配留在后续范围，现有外部工具入口可承接需要的比较。
- 实测答复区分图形可用和工作树状态就绪。SmartGit 对照当时采用各自默认的首批历史规模，记录见 `docs/BANSHU_BENCHMARK.md`。

## Migration Plan

先把已实现行为同步为首套主规格，再归档本变更。应用和现有会话配置沿用已交付版本，部署过程与 `README.md` 一致。
