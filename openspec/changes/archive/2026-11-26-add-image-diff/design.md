## Context

差异请求已在后台读取 Git 快照，按请求编号应用结果。提交、暂存区和工作树共用版本与路径选择逻辑。

## Goals / Non-Goals

支持静态并排预览、透明度、共同比例和同步平移。此次范围限于内置预览，沿用现有 Diff Tools 匹配和启动入口。

## Decisions

- 复用 Git 快照入口，根据文件扩展名进入图片预览。先读本地 LFS 对象。缺失时把该快照的指针送给 `git lfs smudge`，只填充所选对象的缓存。沿用仓库的 LFS 端点、凭据和下载过滤设置，用单次调用的配置将 Git LFS 的钩子安装限制在临时目录。 [Git LFS 对象存储规范](https://github.com/git-lfs/git-lfs/blob/main/docs/spec.md) · [Git LFS smudge 手册](https://github.com/git-lfs/git-lfs/blob/v3.7.1/docs/man/git-lfs-smudge.adoc)
- 后台解码并限制输入字节、解码像素和内存。UI 首次绘制时上传纹理，切换快照后释放，沿用差异请求的过期结果检查。
- 一个图片差异请求并行读取两侧，每侧完成后独立回传。同一请求共享 LFS 缓存目录解析和取消信号。界面按请求编号和栏位应用结果，保留已显示的图片和当前查看模式。
- 选中项改变时，根据比较路径和文件类型同步建立新视图的初始状态，并立即重绘。文本和工作簿在各自工具栏及版本表头下显示加载状态。只有依赖解析结果的控件在加载期间禁用。
- 复用差异双栏和主题语义色。以较大图为基准计算两侧共同比例并对齐左上角，原始像素模式用同一个偏移查看两侧。

## Risks / Trade-offs

- 下载可能因网络、认证、过滤规则或对象缺失而失败。下载有时限，切换选中项时中止，失败后保留可用侧并显示原因。
- 渲染设备的纹理限制可能小于内置解码限制。该侧显示上限提示。
