## Context

Refdesk 的历史和工作树状态在独立任务中读取。旧版把用户手动发现的子模块写为登记仓库，开启预读时可能提前读取其历史。参见 [proposal.md](proposal.md)。

## Goals / Non-Goals

保持父仓库历史优先加载，复用已打开工作树的缓存和活动仓库设置。子模块初始化与更新沿用显式 Git 操作。

## Decisions

- 工作树刷新同时读索引中的 Gitlink 和暂存差异中的 HEAD Gitlink。两者的并集涵盖已暂存新增和移除的子模块。只有子路径能作为独立 Git 工作树打开时才允许点击。
- 工作树结果携带仓库路径和请求编号。仓库树用当前结果挂接子节点，把旧清单中相同的路径合并到该节点。自动发现的路径由父仓库提供，设置文件继续保存登记清单和活动路径。
- 用户打开可用节点时走已有仓库切换入口，按需加载历史和状态。旧清单里的候选仓库在后台预读前按父仓库扫描结果或 Git 父项目查询识别子模块。重启恢复子模块时先通过父仓库的扫描结果解析路径。

## Risks / Trade-offs

- `.gitmodules` 可以包含已失效的路径。以 Gitlink 建树，临时仓库覆盖配置残留、未检出及暂存移除场景。
- 增加 Gitlink 枚举会延长工作树请求。历史仍可独立展示；子模块工作树和历史在进入对应节点时加载。

## Migration Plan

沿用现有会话文件格式。打开父仓库后根据当前 Gitlink 整理仓库树，已有的手动登记仍可读。
