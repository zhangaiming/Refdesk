## ADDED Requirements

### Requirement: 显示当前工作树的 Git 操作状态条

Refdesk SHALL 在提交图和右侧文件区上方显示当前工作树已确认的进行中 Git 操作。状态条左端 SHALL 以专用图标和文字标识摘取、变基和合并。其他已识别且需终端处理的操作 SHALL 使用通用终端图标和明确提示。

#### Scenario: 查看暂停的操作

- **WHEN** 当前工作树有进行中的摘取、变基或合并
- **THEN** 工作区 SHALL 在固定位置显示对应图标、操作名称、已确认的冲突提示及适用的恢复动作
- **AND** 有可确认的当前提交或进度时 SHALL 显示相应信息
- **AND** 冲突、等待继续和执行中的区别 SHALL 通过文字和控件状态表达，同一次操作 SHALL 保持其类型图标

#### Scenario: 当前工作树没有进行中的操作

- **WHEN** Git 确认操作已结束，或用户切到已确认无操作的工作树
- **THEN** 状态条 SHALL 收起，释放占用空间并恢复该工作树的普通提交入口

#### Scenario: 收窄工作区

- **WHEN** 可用宽度不足以展示全部按钮
- **THEN** 适用的「查看冲突」和「继续」SHALL 保持可见，次要动作 SHALL 通过「更多」访问
- **AND** 操作名称和当前处理提示 SHALL 保持可辨认

#### Scenario: 切换主题

- **WHEN** 用户在进行中操作期间切换亮色、暗色或外部主题
- **THEN** 状态条、图标、动作状态及确认框 SHALL 同步使用当前主题，相关状态 SHALL 通过文字和形状区分

### Requirement: 在工作台定位和处理 Git 冲突

Refdesk SHALL 在工作树文件区单独展示有未合并索引条目的文件，并提供查看差异、打开工作树文件与暂存解决结果的入口。

#### Scenario: 从状态条查看冲突

- **WHEN** 用户点击「查看冲突」且当前工作树有未解决冲突
- **THEN** Refdesk SHALL 切到工作树文件视图、展开冲突分组、定位首个冲突文件并展示其差异
- **AND** 若文件筛选挡住该文件，Refdesk SHALL 清除筛选

#### Scenario: 暂存最后一个冲突文件

- **WHEN** Git 确认最后一个冲突文件的未合并索引条目已消失，操作仍在进行
- **THEN** 状态条 SHALL 继续显示操作，更新为当前已确认的下一步
- **AND** 在步骤支持继续时 SHALL 启用对应的继续按钮

### Requirement: 确认跳过或中止 Git 操作

Refdesk SHALL 在执行跳过或中止前显示针对当前工作树和操作步骤的确认框，默认焦点位于「取消」。

#### Scenario: 确认跳过

- **WHEN** 用户选择「跳过当前提交」
- **THEN** 确认框 SHALL 显示可确认的当前提交，并说明本步改动及冲突解决结果可能丢失
- **AND** 跳过单次摘取时 SHALL 说明本次操作将结束

#### Scenario: 确认中止

- **WHEN** 用户选择「中止」
- **THEN** 确认框 SHALL 显示工作树和具体操作，说明 Git 将尝试恢复操作前的状态且本次结果可能丢失
- **AND** 用户按 Esc、关闭确认框或选择「取消」时 SHALL 保持当前 Git 状态

### Requirement: 在右侧提交区编辑变基说明

当正在进行的变基向 Refdesk 请求编辑提交说明时，右侧提交区 SHALL 使用现有提交说明编辑框展示 Git 生成的说明，显示「保存说明并继续」和「取消编辑」。普通提交草稿 SHALL 按工作树独立保留。

#### Scenario: 保存变基说明

- **WHEN** 用户保存当前变基的编辑请求
- **THEN** Refdesk SHALL 将编辑后的说明交给同一个 Git 请求继续变基
- **AND** Git 再请求编辑时 SHALL 显示新说明。变基结束后 SHALL 恢复普通提交草稿

#### Scenario: 取消并重新打开变基说明

- **WHEN** 用户取消编辑
- **THEN** Refdesk SHALL 退出编辑态并保留等待中的 Git 请求，未保存的输入 SHALL 丢弃
- **AND** 状态条 SHALL 提供重新打开同一份 Git 说明的入口，并保留需确认的「中止变基」

#### Scenario: 切换工作树

- **WHEN** 用户在 Git 等待说明时切换工作树并返回
- **THEN** 编辑请求和未取消的输入 SHALL 保留在原工作树，其他工作树 SHALL 显示自己的提交区草稿或详情

## MODIFIED Requirements

### Requirement: 在提交图上方提供仓库操作工具栏

Refdesk SHALL 在中央提交图的页头显示工具栏，从左到右依次放置获取、拉取、推送和刷新。页头首行 SHALL 左对齐标题、右对齐工具栏，供用户在下一行查看历史范围、筛选并定位 HEAD。四个按钮 SHALL 使用与标题栏的外观及 Diff 工具一致的带边框样式。

#### Scenario: 调整窗格或滚动提交列表

- **WHEN** 用户调整左右窗格宽度或滚动提交列表
- **THEN** 页头 SHALL 与中央提交图窗格对齐，并固定在提交列表上方

#### Scenario: 操作当前仓库

- **WHEN** 当前仓库历史已加载，当前工作树无正在执行的 Git 写命令，且已确认无进行中的 Git 操作
- **THEN** 工具栏 SHALL 启用获取、拉取和推送，拉取和推送仍需确认
- **AND** 用户 SHALL 可通过刷新按钮或 F5 刷新当前仓库

#### Scenario: Git 操作暂停等待用户

- **WHEN** 当前工作树有进行中的 Git 操作且无正在执行的 Git 写命令
- **THEN** 工具栏 SHALL 保留获取和刷新，拉取与推送 SHALL 暂时禁用
