## Context

工作树状态和提交历史独立加载。现有 Git 写任务按工作树串行，底部状态栏报告命令执行和结果，文件状态也已读取未合并索引条目。新增一份由 Git 确认的操作状态，随工作树文件状态更新。提交图继续显示真实分支、HEAD 和父提交。

## Goals / Non-Goals

**Goals**

- 让终端和 Refdesk 启动的操作使用同一识别、展示和恢复流程。
- 从状态条进入当前工作树的冲突检查、暂存和恢复动作，复用现有文件区、差异区及确认框。

**Non-Goals**

- 从 Refdesk 发起变基、编辑交互式变基计划、拆分提交或提供三方冲突编辑器。
- 扩展 Git 操作入口至撤销提交、应用邮件补丁或二分查找。

## Decisions

### 按工作树读取 Git 状态

把操作类型、当前步骤标识、可选提交信息和可选进度放入工作树状态。继续沿用只读 Git 封装解析真实路径，例如 `git rev-parse --path-format=absolute --git-path <name>`，兼容关联工作树、子模块及含空格或中文的路径。通过 `--show-ref-format` 识别 reftable，使用 Git 查询其 `CHERRY_PICK_HEAD`、`REVERT_HEAD` 与 `REBASE_HEAD`。路径解析与文件读取出错时保留上次已确认的显示，并暂时禁用恢复动作。

| 操作 | 识别依据 | 展示信息 |
| --- | --- | --- |
| 变基 | `rebase-merge` 或 `rebase-apply`。后者含 `applying` 时按 `git am` 处理 | 能可靠解析时显示原分支、目标基点、当前提交和有效的步骤总数 |
| 合并 | 外层无变基时，用 `MERGE_HEAD` 识别 | 显示已确认的待合并目标。能识别名称时显示名称，否则显示短 SHA |
| 摘取 | `CHERRY_PICK_HEAD` 或明确属于摘取的 `sequencer/todo` | 优先显示当前提交。仅在有可靠依据时显示序列进度 |
| 需终端处理 | 已识别的 `git am`、撤销提交或需要手工修改文件、拆分提交等变基步骤 | 显示已确认的操作与处理提示。无法安全识别步骤时收起无法确定的恢复入口 |

外层变基优先于其重放过程中产生的合并和摘取标记。单独存在的 `REBASE_HEAD` 只提供当前提交候选。摘取队列要区分 `pick` 与 `revert`，避免把队列目录本身当作摘取证据。冲突数来自 porcelain v2 的未合并条目，按路径计数。Git 的本地化提示用于向用户传达错误，结构化标记和索引决定界面状态。

在首次打开、激活工作树、窗口重新获得焦点、F5 及相关 Git 命令返回后读取操作状态。沿用工作树和请求编号拒绝迟到结果。用工作树级文件状态更新冲突总数，局部路径查询仅更新涉及的文件。解析可复用的 Git 路径时避免给每次局部刷新增加重复子进程。状态读取独立于提交历史加载。

### 工作区状态条

在导航栏右侧，从提交图左缘横跨右侧文件区。状态条固定在这些窗格上方。标题行先放图标，再放操作名称。第二行展示冲突数、下一步提示和可确认的进度。宽窗显示恢复动作，空间不足时把适用的跳过、中止移到「更多」。始终保留适用的「查看冲突」和「继续」入口。没有未结束的操作时收起整条。

| 左侧图标 | 形状 |
| --- | --- |
| 摘取 | 上方独立的提交圆点，由弯箭头引向下方的提交线 |
| 变基 | 两个相连的提交点，整段沿箭头移向新基线 |
| 合并 | 两条提交分支汇成一条线 |
| 终端处理 | 终端框内的提示符，供已识别但没有专用图标的操作使用 |

图标采用 16 逻辑点的单色线性样式，对齐标题行，复用当前 `Palette`。类型图标贯穿同一次操作。已识别的复杂变基步骤沿用变基图标并提示在终端处理。冲突用警告色和文字，等待继续用强调色和明确的按钮状态，命令执行中用现有忙碌提示并暂时禁用恢复动作。状态确认失败时用文字反馈，保留刚确认的类型图标。颜色之外始终保留操作标题和说明。

「查看冲突」切到工作树行，展开右侧独立的「冲突」分组，并定位和打开第一个冲突文件的差异。已有文件筛选遮住目标时清除筛选。右侧提交区在工作树视图改为当前操作详情，保留普通提交的输入草稿。冲突项可打开实际工作树文件以便编辑，沿用差异查看与显式暂存。恢复成功并读回结束状态后，恢复普通提交入口。

### 恢复动作与反馈

继续命令使用对应的 Git 子命令。对变基的继续和跳过，按进程设置 `GIT_EDITOR` 为 Refdesk 的编辑器入口。Git 提供提交说明文件，编辑器入口通过本机回环连接交付说明并等待响应。连接用每次操作的随机凭据认证，只接受当前工作树的提交说明文件。Git 一次调用可以发出多个编辑请求，Refdesk 按原顺序逐个处理。结束进程时释放连接。说明内容不写入运行日志。

右上角复用同一个多行输入控件，在待编辑时显示「编辑变基提交说明」和可确认的短 SHA。变基编辑会话及普通提交草稿分别按工作树保存。保存把内容写回 Git 指定的说明文件，再由同一 Git 进程继续。取消编辑撤销当前未保存的输入，右栏离开编辑态，状态条提供「编辑提交说明」重新打开同一请求。状态条仍提供显式中止变基。用户确认后释放等待中的编辑器，并在校验同一变基现场后运行 Git 中止。Git 保持等待，因为在 `reword` 等步骤让编辑器返回失败，可能使下一次 `rebase --continue` 越过原本应编辑的说明。切换工作树时，编辑请求及输入归属原工作树。需要手工改文件、拆分提交或处理无法确认的步骤时，提供终端提示。

跳过和中止使用共享确认框，显示工作树与可用的分支或当前提交信息，默认聚焦「取消」。跳过确认说明当前改动及本步解决结果可能丢失，单次摘取说明操作将结束。中止确认说明将尝试回到操作前，过程中产生的结果可能丢失。跳过仅在 Git 有可跳过的当前提交或补丁时提供，合并的恢复动作包括继续和中止。

恢复请求带上工作树及用户看到的操作类型和步骤标识。入队时和写命令执行前确认工作树与操作仍匹配。继续另行确认索引无未合并条目。用 Git 的原生继续、跳过和中止语义执行。进程退出后通过独立读取校准操作状态、文件、HEAD 和受影响的历史，包括失败后的部分进展。命令执行期间在同一工作树串行写入。暂停普通提交、拉取、推送、检出和发起新的合并或摘取，保留获取、刷新、冲突处理与切换工作树视图。工具栏、快捷键与右键菜单复用同一写入限制。

## Risks / Trade-offs

- 外部命令可能在确认框打开后结束旧操作或停到下一个提交。确认绑定当时的工作树与步骤，发送 Git 命令之前再次读取。状态不匹配时提示刷新后的结果。
- 下一步冲突可以发生在命令已经推进提交历史之后。保留该次 Git 反馈，随后按实际状态更新提交图和冲突分组。
- 变基等待说明时，现有 Git 写入队列保持顺序。状态条给出可重新打开的入口，用户可继续浏览其他工作树。Git 若提前退出，关闭对应编辑请求并读回现场。
- Git 版本、变基后端和序列阶段影响可读到的细节。进度和提交信息允许缺省。每种恢复动作按状态提供，Git 最终核准执行条件。

## Migration Plan

操作状态从当前工作树读取，不需要迁移会话配置或主题文件。状态条和确认框使用已有语义色，旧主题 JSON 沿用现有加载规则。
