## Why

Git 命令退出后，摘取、变基和合并仍可能在等待用户处理。Refdesk 需要识别当前工作树的未结束操作，让用户看到该做什么，并在工作台直接继续、跳过或中止。

## What Changes

- 在提交图和右侧文件区上方显示当前工作树的操作状态条。左端用专用图标标识摘取、变基或合并，已识别但需要从终端处理的其他操作使用通用终端图标。
- 识别 Refdesk 和终端发起的摘取、常规变基和合并。根据 Git 确认的当前步骤和索引冲突记录展示进度、冲突数量与可执行入口。
- 提供「查看冲突」「继续」「跳过当前提交」和「中止」。按操作类型和步骤展示按钮，跳过和中止要求确认，窄窗将次要动作收入「更多」。
- 在写入前复核工作树和步骤，写入后用 Git 状态核对实际结果，覆盖继续或跳过后遇到下一处冲突的情况。
- 变基请求编辑提交说明时，复用右上角的说明编辑区。保存后继续原 Git 操作，取消编辑后可重新打开同一请求，普通提交草稿按工作树保留。
- 接手已经开始的变基。编辑变基计划和拆分提交从终端处理。

## Capabilities

### Modified Capabilities

- `desktop-workbench` 增加操作状态条、图标、冲突导航和确认交互，并调整仓库工具栏的可用条件。
- `git-operations` 增加按工作树识别进行中的操作、限制冲突期间的写入、执行恢复动作并校准实际结果。

## Impact

涉及 Git 命令封装、工作树状态和请求归属、提交图上方布局、文件分组与差异导航、确认框及共享主题色。实现阶段更新使用说明、待办和验收记录。
