## Context

索引操作完成后先更新已确认的界面数据。统一完成流程随后读取该工作树的文件状态与子模块。

## Decisions

- 以文件状态和包含子模块的状态两种范围调度。只对缓存已识别为普通文件的明确路径复用近期的子模块快照。初次加载、手动刷新、整仓操作、缓存过期和涉及 Gitlink 或 `.gitmodules` 的状态沿用完整读取。
- 文件查询发现 HEAD 已变化或存在子模块相关改动时补读子模块。
- 普通文件索引操作完成后，将同一工作树的全量校准放在 250 毫秒合并窗口末尾。成功反馈、局部更新和需要的定向读取立即进行。已有请求归属检查继续丢弃过期结果。

## Risks / Trade-offs

- 合并窗口只影响最终校准。读取范围扩大后立即调度。

## 取消暂存候选命令评估

用 Git 2.53.0.windows.1 从同一索引分别运行现有的 `git --literal-pathspecs restore --staged -- <paths>` 和候选的 `git --literal-pathspecs reset --quiet --no-refresh HEAD -- <paths>`。无初始提交用例对照现有的 `rm -f --cached --ignore-unmatch` 路径。

- 修改、部分暂存、新增、删除、重命名路径对、Gitlink、中文和特殊字符路径、无初始提交、稀疏检出和未合并索引条目均得到相同的索引条目和标志。工作树内容及 HEAD、ORIG_HEAD 相同。普通文件另核对索引 stat 缓存，两条命令的结果相同。
- 候选命令继续触发 `post-index-change`，跳过 `post-checkout`。依赖 `post-checkout` 的自定义钩子会失去这次回调。对照中注入返回码 7 的 `post-checkout`，现有命令在索引写入后报告失败，候选命令报告成功。
- 对索引和 HEAD 均无匹配项的路径，现有命令报错，候选命令返回成功且索引条目没有变化。若后续采用候选命令，需保留字面路径及非空路径约束，并以定向状态确认可以显示的变化。
- 在下述 92,574 条索引且启用 Git LFS 3.7.1 钩子的隔离工作树中，对同一个已暂存的普通新增文件交替运行两条命令，每条 3 次。现有命令的中位数为 1,514 ms，每次执行 `post-checkout`。候选命令的中位数为 154 ms。两组均从索引移除该项并保留工作树文件。
- 本轮采用候选命令，保持无初始提交时的索引移除方式。成功后定向读取明确路径，失败时走错误反馈。未来的设置面板提供兼容选项，供依赖取消暂存时执行 `post-checkout` 的仓库启用。

## 暂存拆分计时

同一隔离工作树从真实 HEAD 建立 92,574 条、约 12.66 MiB 的索引，只写出测试文件。各组使用相同索引起点，交替执行 5 次单路径 `git add`，每次生成新的随机文件内容。普通文件核对 blob 大小，LFS 文件核对索引中的指针。Git LFS 为 3.7.1。

| 样本 | 总耗时 | 读索引 | 写索引 | 路径扫描 | LFS 子进程 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 普通 64 KiB | 160 ms | 9 ms | 29 ms | 6 ms | — |
| LFS 64 KiB | 1,118 ms | 9 ms | 29 ms | 6 ms | 999 ms |
| 普通 8 MiB | 351 ms | 9 ms | 30 ms | 6 ms | — |
| LFS 8 MiB | 1,156 ms | 9 ms | 30 ms | 6 ms | 1,034 ms |

表格是各指标的中位数。单独启动 `git --version` 的中位数为 56 ms。Trace2 中的 LFS 子进程存活时间与部分 Git 阶段重叠。额外一次详细跟踪显示 Windows 通过 `sh.exe` 启动 LFS，LFS 在初始化时还执行 7 次 Git 仓库和配置查询，并检查钩子。隔离工作树的文件布局与真实仓库有差异，计时用于定位阶段。

## 显式多选暂存

工作树的未暂存分组用 Ctrl+单击增减选择。文件标题和已选行的右键菜单均可提交一次暂存。通过字面路径限定的 `git add` 一次启动 Git、读写索引并复用该进程内的 LFS 过滤器。多路径通过标准输入传递 NUL 分隔的路径列表。范围不确定的文件以 Git 读回结果校准。

同一隔离索引分别暂存一个 64 KiB 和一个 8 MiB 的 LFS 文件，三轮交替对照。分两次执行的中位数为 2,311 ms，合并一次执行为 1,150 ms。LFS 过滤器由两次启动降为一次，两个文件的索引对象及指针一致。合批中加入不存在的路径时返回 128，索引与操作前一致。

- 用户的一次多选是一个批次。路径失效或必需的过滤器失败时统一报告这一批失败，保留原分组和选择。用户可以刷新以读取真实状态。索引失败也可能已经留下本地对象或过滤器的副作用。
- 单文件暂存在触发后立即调度，按其操作独立反馈。单个 LFS 文件依然需要启动过滤器。
- 普通文件可进一步测量复用可信工作树身份是否能省掉每次启动 `rev-parse`。需要能发现目录、链接或 `.git` 被替换，否则可能把写入发到另一个工作树。目前保留校验。绕过原生过滤器或手写 LFS 指针会改变属性、转换、对象落盘和自定义过滤器的语义。
