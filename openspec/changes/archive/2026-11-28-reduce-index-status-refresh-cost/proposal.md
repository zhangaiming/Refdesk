## Why

普通文件暂存后仍需要校准完整文件列表。每次同时重读子模块和连续执行多个全量扫描，会增加大型工作树的后台 I/O。取消暂存的检出钩子，以及逐文件暂存时重复启动 Git 和 LFS 过滤器，也会增加耗时。

## What Changes

- 普通文件暂存和取消暂存的自动校准复用已读取的子模块列表。需要重新确认子模块的操作继续读取完整状态。
- 短时间内连续完成的同一工作树普通文件索引操作合并待执行的全量校准。
- 取消暂存使用路径限定的索引重置，并读取真实文件状态后更新分组。
- 允许在工作树文件区明确多选，一次暂存全部所选文件。单文件暂存沿用直接调度。

## Capabilities

### Modified Capabilities

- `git-operations` 的索引操作、后台校准和文件选择。

## Impact

- 工作树文件区、Git 操作完成计划、仓库状态任务和 Git 状态测试。
