## Context

仓库已有调度、Git 拓扑和差异逻辑的 Rust 用例。Git 用例使用临时目录，仍可能继承签名、钩子和外部仓库环境。工作簿目前有数据模型与进程限制测试，还需要执行实际工作簿解析入口。

## Goals / Non-Goals

**Goals**

- 让本地验证和 Windows CI 使用同一组检查命令。
- 使用真实 Git 与真实 XLSX 固定关键回归边界。

**Non-Goals**

- 产品行为、发布打包和视觉验收自动化。

## Decisions

- 在测试构建的 Git 命令入口隔离环境。清除继承的 Git 环境变量，禁用系统、全局配置和默认模板，保留各夹具自己的仓库配置。
- 用临时裸仓库和两个工作树形成分叉，调用生产拉取操作，验证失败后本地 HEAD 保持不变。用同一夹具验证可快进路径。
- 用 Cargo 集成测试定位本轮 Refdesk 可执行文件。按实际工作簿进程协议发送两个最小 XLSX 文件，检查返回的工作表、值、公式和稀疏坐标。
- 使用 GitHub 托管 Windows x64 MSVC runner 执行格式、Release Clippy 和 Release 测试。版本锁由 Cargo.lock 管理，UI 场景继续沿用隔离会话的实际运行验收。

## Risks / Trade-offs

- 本地可用工具链和 CI 目标可能不同。验证记录写明实际工具链、执行结果和仍待跑的场景。
- 测试仓库应可由并行用例独立使用。隔离设置只落在单个子进程，测试夹具全部保存在各自的临时目录或代码仓库。
