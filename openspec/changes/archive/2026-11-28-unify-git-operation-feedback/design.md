## Context

现有索引写入在命令完成后先更新缓存，再由 Git 状态校准。其他写操作的完成事件统一清空选区并重载提交图和状态。

## Decisions

- 操作携带类型化成功计划，统一决定直接可确认的更新、定向读取与最终校准范围。成功先发给界面。局部更新后的定向读取与完整校准在绘制后排队。
- 索引和丢弃校准工作树状态。丢弃只移除定向读取已经确认恢复的已跟踪普通文件行。大批量路径交给完整状态。创建分支与标签立即补确认的引用，随后刷新历史。获取和推送由完整历史确认远端、上游计数与引用。
- 提交、摘取、切换、检出、合并和拉取都确认实际 HEAD。合并与拉取还比较命令前的真实 HEAD。只有能定位到已缓存提交行时才局部放置 HEAD 标记。新行和拓扑由完整历史构建。仓库和分支标题可使用确认后的当前分支。发生 HEAD 变化时，选中的工作树文件用新的比较基准。
- 定向和完整结果使用工作树及请求编号。后来的操作接续同工作树尚未完成的校准范围。失败路径反馈错误并保留当前显示。合并类操作失败且可能留下冲突时，可随后只读索引和工作树。

## Risks / Trade-offs

- 缓存提交图使用原始 Git 父边。新提交或缓存不可用时，由完整历史决定呈现。确认失败时保留现有数据，继续完整校准。
- 局部引用和 HEAD 显示只覆盖可确认的字段。跟踪关系、领先落后和新图仍以最终数据为准。

## 操作与校准范围

| 操作 | 局部显示或定向读取 | 完整校准 |
| --- | --- | --- |
| 暂存、取消暂存、暂存全部 | 普通路径先换组。复杂路径定向读取后更新行及对应差异 | 工作树 |
| 丢弃未暂存改动 | 只移除定向确认已恢复的普通文件行。候选超过 32 个路径时直接校准 | 工作树 |
| 从指定提交创建分支或标签 | 写入成功后显示确认的名称、目标 SHA 和已加载目标行的标记 | 引用和历史 |
| 提交、摘取 | 读取真实 HEAD 及父提交。只有能匹配到已加载行时更新标记 | 引用、历史和工作树 |
| 检出、切换、新建并切换分支 | 确认后更新仓库和分支标题。已加载目标行显示 HEAD | 引用、历史和工作树 |
| 合并、拉取 | 对比写入前后的实际 HEAD。确认移动且找到缓存行时更新标记 | 引用、历史和工作树 |
| 获取、推送 | 先反馈 Git 结果。远程引用、跟踪关系和计数由后续读取确认 | 引用和历史 |
